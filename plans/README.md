## Findings considered and rejected (do not re-audit without new evidence)

- **setState after unmount in `UnlockScreen.unlock()`** (`finally { setUnlocking(false) }` after `onUnlocked()`): React 18+ removed the unmounted-setState warning; the write is a no-op. Harmless.
- **Badge race between cert-warning `!` and match count** (`warnedTabs` check vs awaited badge write): cosmetic flicker at worst, self-heals on next navigation. Not worth the serialization machinery.
- **pwgen modulo bias** (`rand()` uses `% max` over 32-bit CSPRNG output): bias is cryptographically negligible for ≤~95-char alphabets; entropy source (crypto.getRandomValues) is correct.
- **`<all_urls>` host permission breadth**: defensible tradeoff for focus-driven autofill; documented rather than narrowed. The redundant `activeTab` permission could be dropped opportunistically.
- **"Reopen last vault" direction suggestion**: already implemented — `UnlockScreen.tsx` persists/restores the last cloud source (`saveLastCloud`/`clearLastCloud`) and key-file handle. Stale evidence; rejected.
- **Vite 6 → 8 migration**: deferred until `@crxjs/vite-plugin` publishes a Vite-8-verified release; upgrade them together. Do the cheap within-major bumps opportunistically (crxjs 2.0.3→2.7.x, tailwind 4.1→4.3, playwright patch).
- **Per-render tree walks in Popup/Panel (missing `useMemo`), per-keystroke `getEntry` round-trips, O(n) vault scans without a uuid index, per-entry page-URL re-parsing in the matcher**: real patterns, irrelevant at realistic personal-vault sizes. Revisit only with evidence of large-vault users.
- **Popup-create auto-saves while panel edits need explicit Save** (divergent persistence models): deliberate-looking product split; flagged for a product decision, not an engineering fix.
- **Dead i18n scaffolding + Firefox build configs**: kept intentionally (see plan 017's out-of-scope rationale; Firefox port was declined by the maintainer for now — was direction finding D4).
- **Onboarding batch (`.env.example` for `VITE_DROPBOX_CLIENT_ID`/`VITE_GDRIVE_CLIENT_ID`, `CLAUDE.md`)**: was findings table #15 — explicitly declined by the maintainer in this session.
- **vitest intermittent worker-fork crash**: not reproduced during the audit (102/102 pass); bounded mitigation (`pool: 'threads'`) documented inside plan 015's STOP conditions if it resurfaces in CI.
- **README "Manual Verification Checklist" automation**: already done — the E2E suite exists precisely for it (design doc `docs/superpowers/specs/2026-06-22-quickkee-e2e-tests-design.md`).
